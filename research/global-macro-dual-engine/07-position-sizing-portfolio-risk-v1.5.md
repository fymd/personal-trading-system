# 买卖点与组合风险控制 V1.5

- 日期：2026-11-10
- 状态：研究规格初稿；未完成程序实现、历史回测、样本外测试或模拟交易验收。
- 适用：V1.3龙头短线引擎（约3–5个交易日）与V1.4趋势波段引擎（约2–8周）。
- 目标：把单笔交易风险、组合总风险、相关性、流动性、执行约束和账户回撤纳入统一许可流程。
- 所有比例、阈值、窗口均为待验证假设，不是已验证参数或实盘建议。

## 1. 风险控制的层级

风险控制按优先级自上而下：
1. 数据质量与交易制度闸门：关键数据失效、交易状态不明、价格限制错误时，阻止依赖该数据的订单。
2. 事件不确定性闸门：沿用U0–U3；U2/U3不得因评分高而新开仓。
3. 市场环境闸门：V1.1决定市场风险状态和新开仓风险预算。
4. 策略/标的闸门：V1.2、V1.3、V1.4提供板块、个股和形态资格。
5. 单笔风险预算：计算仓位和理论止损风险。
6. 组合风险预算：合并行业、主题、因子、相关性和总风险。
7. 执行前检查：流动性、涨跌停、停牌、T+1、可成交量、费用和滑点。
8. 持仓监控和退出：逻辑失效、止损、时间退出、组合熔断。

任何上层否决都优先于下层评分和仓位公式。风险预算是上限，不是必须用满的额度。

## 2. 统一交易风险定义

### 2.1 单笔计划风险
对多头交易，定义：
- equity：下单决策时账户净值；
- risk_fraction：该笔交易允许承担的净值比例；
- entry_price：计划可成交入场价；
- stop_price：预先定义的失效/止损参考价；
- costs_estimate：预计买卖费用、滑点和冲击成本；
- gap_buffer：跳空、流动性和价格限制导致的额外风险缓冲。

风险预算金额：
`risk_budget = equity × risk_fraction`

每股计划风险：
`risk_per_share = entry_price - stop_price + estimated_round_trip_cost_per_share + gap_buffer_per_share`

初步股数：
`qty_risk = floor_to_lot(risk_budget / risk_per_share)`

实际下单数量还必须满足现金、流动性、组合暴露和交易制度限制。若entry_price <= stop_price、stop_price不可定义或风险数据缺失，拒绝计算并标记NO_TRADE。

### 2.2 计划风险不等于最大可能损失
A股跳空、跌停、停牌、流动性枯竭和无法成交可能使实际损失超过计划风险。系统不得把止损价当成保证成交价。每笔交易记录计划风险、压力风险和实际风险。

### 2.3 价格与成本口径
入场价使用当时可执行价格或保守成交模型，不得直接使用产生信号的收盘价假设同价成交。成本按历史时期、证券类别和实际费率规则配置。买卖佣金、印花税、过户费、滑点、冲击成本及未成交机会成本分别记录。

## 3. 风险预算与仓位规模

初始研究参数（待验证）：
- 龙头短线单笔风险：净值的0.25%–0.50%；
- 趋势波段单笔风险：净值的0.50%–0.75%；
- 所有持仓计划风险总和：净值的2%–3%以内；
- 单一股票市值暴露上限、单一行业/主题暴露上限另行设定，并按流动性与市场状态动态收紧。

以上仅用于建立回测起点，不构成推荐配置。不得机械地认为趋势仓风险额度一定高于短线仓，需通过策略波动和尾部损失数据验证。

市场风险预算系数沿用V1.1初始假设：
- 积极参与：1.00；
- 谨慎参与：0.60；
- 观望：0.25；
- 风险控制：0。
最终单笔预算：
`effective_risk_budget = base_risk_budget × market_regime_multiplier × strategy_multiplier × portfolio_multiplier`

任何系数不得把风险预算提高到基础上限以上。U2/U3、数据失败、账户熔断和执行不可行时，系数直接为0。

## 4. 仓位约束的多重上限

最终可下单数量取以下约束的最小值：
`qty_final = min(qty_risk, qty_cash, qty_position_cap, qty_liquidity, qty_sector, qty_portfolio)`

- qty_risk：按止损距离计算的风险数量。
- qty_cash：可用现金和资金占用约束。
- qty_position_cap：单票市值上限。
- qty_liquidity：成交量参与率和市场冲击约束。
- qty_sector：行业/主题剩余暴露额度。
- qty_portfolio：组合总风险剩余额度。

若任何关键约束无法计算，不能默认为无限额度；应拒绝新单或进入人工复核状态。

## 5. 组合风险账本

每个交易日及每次下单前维护：
- 账户净值、现金、持仓市值、未实现盈亏、已实现盈亏；
- 每笔计划风险、压力风险、止损价、持仓时间和策略引擎；
- 行业、概念主题、产业链环节、地域、风格因子及主要宏观敏感度；
- 单票、行业、主题、策略引擎和全组合暴露；
- 过去20/60日收益相关性、下行相关性和共同风险事件；
- 流动性、平均成交额、买卖价差、成交量参与率和退出天数估计。

风险账本同时保留“当前市值暴露”和“止损计划风险”。二者不可混为一谈。相关性是动态估计量，历史相关性低不保证危机时仍低。

## 6. 集中度与相关性

初始研究限制（待验证）：
- 单只股票市值占净值上限：10%；
- 单一行业市值暴露上限：25%；
- 单一高度相关主题/产业链暴露上限：30%；
- 全部持仓计划风险上限：净值2%–3%。

这些上限是测试用约束，不是通用最优值；应按策略、流动性、市场状态和行业分散程度做敏感性测试。

相关性处理：
1. 采用滚动收益相关性，并观察下行样本相关性。
2. 对短历史、停牌、涨跌停和低流动性证券，相关性估计标记低置信度。
3. 同一主题不同名称、上下游公司、共同客户/供应商、同一宏观因子暴露应补充经济关联标签。
4. 多引擎重复持有同一股票时，按一个标的合并风险，不得重复计入分散化。
5. 相关性突然上升、行业宽度同步恶化时，降低组合乘数或停止增加相关敞口。

## 7. 流动性与容量

下单前计算：
- ADV20/ADV60：20/60日平均成交额；
- participation_rate：计划订单金额/预估当日成交额；
- estimated_exit_days：持仓市值/可接受日均退出金额；
- spread、波动率、盘口深度（若有可靠数据）。

初始回测假设：单日订单金额不超过标的日成交额的5%，并对1%、2%、5%、10%参与率做敏感性分析。若只有日线数据，成交额参与率只能做粗略近似，不能声称精确模拟盘口成交。

流动性恶化、成交额骤降、连续一字涨跌停或停牌时，退出时间可能延长。压力测试应模拟无法在计划价成交的情况。

## 8. 止损、止盈与退出框架

### 8.1 止损设定
止损应在入场前定义，依据策略形态和逻辑失效点。结构止损、波动率止损和基本面失效条件可组合，但须避免事后选择最宽松的规则。

### 8.2 龙头短线退出
- 关键承接/突破结构失效；
- 龙头地位丧失且板块扩散、梯队和情绪同步转弱；
- 预设时间窗口内未出现预期走势；
- 市场进入退潮或风险控制状态；
- 出现重大负面事实或U等级升级。

### 8.3 趋势波段退出
- 行业景气关键证据反转；
- 公司盈利质量、现金流或核心经营假设被证伪；
- 中期趋势结构和相对强度持续破坏；
- 估值/盈利预期出现重大不匹配；
- 达到时间退出条件或组合风险约束。

### 8.4 止盈与移动止损
不把固定收益目标当作唯一退出条件。可研究分批止盈、趋势跟踪退出和风险回报比，但必须事先定义，避免看到结果后改变规则。移动止损只能按规则向有利方向调整，不得因亏损而扩大风险预算。

## 9. 账户级回撤控制与熔断

建议测试多个回撤阈值，而不是先验确定唯一最优值：
- 账户从历史净值高点回撤达到5%：进入观察/降低新开仓风险；
- 达到8%：暂停新增风险，复核策略、数据和执行；
- 达到10%：进入强制风险审查，原则上暂停新开仓，直至完成复盘和重新授权。

上述阈值是研究情景，不代表已验证的最优风控线。回撤以扣除费用后的净值计算，并同时观察日内、收盘和滚动峰值回撤。

熔断后：
1. 不自动清仓所有持仓；逐笔评估流动性、止损可执行性和风险。
2. 不通过提高仓位或加仓摊平来快速恢复净值。
3. 查明损失来自市场状态、策略失效、数据错误、执行偏差还是参数过拟合。
4. 只有完成复盘、修复和模拟验证后才允许恢复风险预算。

## 10. 组合压力测试

至少建立以下场景：
- 全市场指数快速下跌、市场宽度骤弱；
- 同一行业/主题持仓同步下跌；
- 美元、实际利率、汇率或商品价格出现不利跳变；
- 波动率飙升、相关性上升、流动性收缩；
- 多只持仓同时跳空低开或跌停无法卖出；
- 停牌、重大公告、财报暴雷；
- 市场成交额大幅萎缩，退出天数延长；
- 两个引擎同时发出信号导致风险重复叠加。

每个情景记录组合损失、最大单票损失、行业贡献、预计退出时间、现金需求和无法退出的持仓比例。情景参数必须有历史依据或清晰标注为假设。

## 11. A股交易制度与执行

回测和实盘模拟必须按证券类别、交易板块和历史时期配置：
- T+1可卖出限制及当日新买持仓；
- 主板、创业板、科创板及风险警示证券的涨跌幅限制差异；
- 新股上市初期等特殊交易规则；
- 停牌、复牌、临时停牌和退市整理状态；
- 涨停买入排队、跌停卖出排队及无法成交；
- 最小交易单位、价格最小变动单位、委托价格限制；
- 佣金、印花税、过户费和历史费率变化。

不得使用当前规则回填全部历史时期。具体交易制度数据应按交易所规则和生效日期维护，版本化存档。

## 12. 交易前检查清单

每笔新单提交前，程序应依次确认：
1. 数据时间戳和质量检查通过；
2. U等级允许交易；
3. 市场状态允许新增风险；
4. 引擎信号状态为ENTERABLE；
5. 入场价、止损价和每股风险有效；
6. 单票、行业、主题和组合剩余额度充足；
7. 流动性、参与率和预计退出能力合格；
8. 现金、T+1、涨跌停和委托规则允许；
9. 费用、滑点和压力缓冲已计入；
10. 信号未过期、价格未偏离可接受范围；
11. 订单数量按所有约束取最小值；
12. 生成可审计的订单理由和风险快照。

任一关键项失败：NO_TRADE或MANUAL_REVIEW，不得自动绕过。

## 13. 核心伪代码

```python
def evaluate_new_order(signal, account, portfolio, market, data):
    if not data.quality_pass:
        return reject("DATA_QUALITY_FAIL")
    if signal.uncertainty_level in ("U2", "U3"):
        return reject("UNCERTAINTY_GATE")
    if not market.new_risk_allowed:
        return reject("MARKET_RISK_GATE")
    if signal.status != "ENTERABLE":
        return reject("SIGNAL_NOT_ENTERABLE")
    if not execution_rules_pass(signal, data):
        return reject("EXECUTION_CONSTRAINT")

    risk_budget = (
        account.equity
        * signal.base_risk_fraction
        * market.risk_multiplier
        * portfolio.risk_multiplier
    )
    per_share_risk = (
        signal.entry_price - signal.stop_price
        + signal.cost_buffer
        + signal.gap_buffer
    )
    if per_share_risk <= 0:
        return reject("INVALID_RISK_DISTANCE")

    qty_risk = floor_to_lot(risk_budget / per_share_risk)
    caps = [
        qty_risk,
        cash_cap(account, signal),
        single_name_cap(account, portfolio, signal),
        liquidity_cap(signal, data),
        sector_cap(portfolio, signal),
        portfolio_risk_cap(account, portfolio, signal),
    ]
    qty = min(caps)
    if qty <= 0:
        return reject("NO_REMAINING_CAPACITY")

    return approve_for_execution(qty, risk_snapshot(signal, account, portfolio))
```

伪代码为逻辑示意，正式实现还需处理卖出方向、部分成交、撤单、订单有效期、风险预算并发占用和成交后账本更新。

## 14. 必须通过的测试与反例

1. 单票风险预算充足但行业额度已满：拒绝新增。
2. 两个引擎对同一股票同时发信号：合并计算，不重复分散。
3. 单票止损距离很小但流动性很差：由流动性约束限制数量。
4. 计划止损价低于跌停价且无法卖出：压力风险不得按止损价封顶。
5. 买入当日触发卖出信号：按T+1和实际制度处理，不得虚构当日卖出。
6. 账户回撤触发熔断：停止新增风险，保留逐笔退出判断。
7. 市场相关性由低转高：组合风险乘数下降或暂停新增相关敞口。
8. 成交额骤降：重新计算容量和预计退出天数。
9. 交易费用或滑点缺失：不得输出净收益回测结论。
10. 订单价格超过信号有效区间：信号过期，拒绝追价。
11. 多个订单同时提交：先预留风险预算，避免并发订单超额占用。
12. U3事件期间评分很高：仍然拒绝基于该事件开仓。

## 15. 回测与验收

分别对龙头短线、趋势波段和合并组合评估：
- 净值曲线、复合收益、最大回撤、回撤持续时间；
- 单笔计划风险与实际损失偏差、尾部损失；
- 风险预算利用率、仓位、换手、现金比例；
- 行业/主题集中度、相关性、压力损失；
- 流动性容量、参与率、未成交率、退出天数；
- 费用和滑点对策略收益的侵蚀；
- 熔断触发频率、触发后恢复条件和机会成本；
- 不同市场状态、不同波动环境和样本外表现。

开展参数敏感性测试：单笔风险、总风险、行业上限、参与率、回撤阈值、滑点缓冲等。不得只挑选收益最高的参数；同时报告稳定区间和最差合理情景。

## 16. 未决事项

1. 风险预算比例与两引擎风险分配如何通过样本外结果确定。
2. 单票、行业、主题暴露上限是否按波动率和流动性动态调整。
3. 相关性窗口、下行相关性和经济关联标签如何融合。
4. 账户熔断阈值及恢复流程如何定义。
5. 日线回测如何保守模拟盘中触发、跳空和涨跌停排队。
6. 历史交易费率、交易规则和最小单位数据源。
7. 多订单并发的风险预留与部分成交账本。
8. 龙头与趋势引擎同股、同主题信号冲突时的优先级。

## 17. 验收标准

V1.5只有在以下条件满足后才可进入整合：
- 单笔风险和组合风险可逐笔复算；
- 所有订单受现金、流动性、集中度和交易制度约束；
- A股历史规则和成本按生效日期配置；
- 跳空、跌停、停牌和相关性上升等压力情景有保守处理；
- 熔断规则可复现且不会自动造成不合理强平；
- 回测、样本外与模拟交易报告完整披露；
- 所有参数仍有适用边界和失效条件记录。

**结论：** V1.5是风险控制规格初稿，不是实盘仓位建议。风险预算公式和阈值必须经过历史数据、压力测试和模拟交易验证。
