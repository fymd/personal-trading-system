# 第25阶段：统一数据架构与回测数据底座 V1.0

- 日期：2026-11-10
- 状态：架构规格初稿；尚未接入生产数据或运行正式回测
- 目标：建立可点时查询、可审计、可复现的统一数据底座，支撑市场研究、龙头短线、趋势波段及双引擎组合验证。

## 1. 核心原则

每条交易信号都必须能回答：当时知道什么、何时知道、依据什么数据、为什么产生信号、是否真实可成交，以及结果能否独立复现。

先验收数据正确性，再讨论策略收益。数据质量否决优先于评分和交易信号。不能取得可靠历史数据时，必须缩小研究范围或降低结论置信度，不得用今天的数据冒充历史点时数据。

## 2. 六层数据架构

- L1 原始数据层：行情、财务、公告、行业、宏观和交易制度原始记录。
- L2 标准化数据层：统一证券主键、行业分类、交易日历、字段、单位和代码映射。
- L3 点时数据层：发布日期、可用时间、修订版本、历史成分和有效时间。
- L4 指标与特征层：市场宽度、情绪、板块、龙头、趋势和宏观指标。
- L5 信号与组合层：双引擎信号、风险预算、订单模拟、持仓和退出。
- L6 验证与审计层：回测结果、样本外测试、压力测试、实验版本和审计日志。

各层必须保留来源和计算关系。最终评分必须能追溯到原始记录、计算公式和指标版本。

## 3. 统一基础实体

| 实体 | 建议主键 | 内容 |
|---|---|---|
| security_master | security_id | 稳定证券主键、代码映射、板块、上市/退市时间 |
| trading_calendar | exchange + date | 交易所日历和交易状态 |
| industry_master | industry_id + version | 行业分类及层级 |
| industry_membership | security_id + effective_time | 历史行业归属 |
| market_daily | security_id + date | OHLC、成交量额、复权信息 |
| financial_reports | security_id + report_id + revision_id | 财报数据及披露信息 |
| corporate_events | security_id + event_id | 公告、预告、分红、增发、重组等 |
| macro_observations | indicator_id + period + revision_id | 宏观指标及首次公布/修订值 |
| market_indicators | indicator_id + date + version | 市场宽度、成交、波动等 |
| strategy_signals | signal_id | 双引擎信号及失效条件 |
| simulated_orders | order_id | 委托、成交、撤单和执行成本 |
| portfolio_daily | portfolio_id + date | 净值、现金、持仓和风险 |

证券代码不能作为永久主键。证券可能更名、转板、退市或发生代码变化，应使用内部稳定的security_id，代码作为带有效时间的属性。行业分类也必须保留历史版本。

## 4. 四种时间必须区分

- event_time：事件实际发生时间或数据统计所属时间。
- publish_time：信息正式披露时间。
- available_time：数据实际可被策略使用的时间。
- ingest_time：数据进入本系统的时间。

历史时点t只允许读取available_time不晚于t的数据：

`D(t) = {x_i | available_time_i <= t}`

财报统计期不等于披露时间；盘后披露不能回填为盘中已知信息。宏观数据必须保留首次公布值和后续修订值。供应商补录时间不得冒充真实发布日期。原始时区、标准化时间和交易日归属都要保留；A股交易决策采用交易所当地时间。

## 5. 点时数据版本规范

关键记录至少保存：
`record_id`、`entity_id`、`field_name`、`field_value`、`event_time`、`publish_time`、`available_time`、`ingest_time`、`revision_id`、`source_id`、`quality_status`、`valid_from`、`valid_to`。

必须能够恢复历史时点当时可见的版本，而不仅是数据库当前最新值。修订不得覆盖原始版本。

## 6. 历史股票池与幸存者偏差

建立`universe_membership_daily`，至少包含security_id、trade_date、listed_status、board_type、industry_id、tradable_status、suspension_flag、risk_warning_flag、special_rule_flag、inclusion_reason、exclusion_reason。

历史股票池必须覆盖当时上市股票、后来退市股票、停复牌证券、不同板块、特殊交易规则证券及历史行业成分。区分：
1. 全市场研究股票池；
2. 龙头候选股票池；
3. 趋势候选股票池；
4. 当日实际可交易股票池。

停牌股票可属于研究股票池，但不属于当日可交易股票池。不能用当前存续股票反推历史样本。

## 7. 数据源等级与质量状态

来源等级：
- S1：交易所、监管机构、央行、统计部门原始发布。
- S2：正规授权金融数据供应商，需记录版本和授权范围。
- S3：公开财经网站、行业协会、研究机构，主要用于辅助和交叉核验。
- S4：社交媒体、论坛、传闻，只能作为线索，不直接驱动交易。

质量状态：
- VALID：通过检查；
- MISSING：缺失；
- SUSPICIOUS：异常待核验；
- REVISED：存在修订；
- STALE：过期；
- UNVERIFIED：尚未验证；
- REJECTED：禁止用于正式回测。

质量检查覆盖完整性、合法性、连续性、一致性、时间性、唯一性和修订性。缺失不得自动补零；异常价格需核查除权、停牌和数据错误；重复记录按版本规则处理。关键数据质量失败不能被高评分抵消，必须阻断依赖该数据的信号。

## 8. 双引擎统一数据接口

两个引擎共享基础数据，但保留独立信号、交易、退出和归因。

统一信号至少包含：
`signal_id`、`engine_type`、`security_id`、`signal_date`、`signal_time`、`available_data_cutoff`、`signal_type`、`market_regime`、`sector_id`、`score_version`、`data_snapshot_id`、`invalidation_price`、`max_entry_price`、`planned_risk`、`permission_status`、`rejection_reason`。

data_snapshot_id用于复现当时使用的数据快照。组合层统一处理现金、风险预算、订单模拟、持仓和退出，禁止两引擎重复使用资金或风险额度。

## 9. 实验可复现性

每次实验必须登记experiment_id、strategy_version、data_version、universe_version、parameter_version、回测区间、训练/验证/样本外区间、cost_model、execution_model、code_version和result_status。

实验结果保留原始结果、成本后结果、成本敏感性、样本外结果、失败案例、参数变更和审计结论。不得因结果不佳覆盖或删除旧实验。

命名示例：`EXP-MKT-001`市场宽度、`EXP-LDR-001`龙头短线、`EXP-TRD-001`趋势波段、`EXP-PF-001`双引擎组合。

## 10. 自动化数据测试

正式策略回测前至少通过：
1. 时间穿越测试：信号不能读取未来可用数据。
2. 历史股票池测试：退市股票和历史行业成分不遗漏。
3. 财务披露测试：未披露财报不能进入特征。
4. 修订版本测试：可恢复首次公布值。
5. 行情完整性测试：缺失、重复、异常均有标记。
6. 交易制度测试：历史涨跌停和交易规则按证券类别、日期还原。
7. 复权测试：除权除息处理前后一致。
8. 停复牌测试：停牌期间不能虚拟成交。
9. 信号复现测试：同数据快照、参数和代码版本可复现同一信号。
10. 组合资金测试：两引擎不得重复使用现金或超额风险预算。

任何时间穿越测试失败，都不得进入正式策略收益评估。

## 11. 分阶段建设顺序

- P0：证券主表、交易日历、历史股票池、日行情、复权、停复牌、涨跌停和点时机制。
- P1：财报、公告、宏观数据、历史行业分类与成分。
- P2：市场宽度、情绪、板块指标、双引擎信号、订单和组合风险账本。
- P3：实验管理、自动报告、样本外验证和审计。

第一批核心数据是证券主表、交易日历、历史股票池、日行情和交易制度，而不是一开始接入所有宏观指标。

## 12. 尚未解决的数据风险

1. 历史行业分类和概念板块数据的供应商质量、完整性与成本。
2. 历史财务一致预期能否取得真正点时版本。
3. 逐笔与盘口数据的历史覆盖范围、质量和成本。
4. 交易制度规则能否按证券类别和日期准确还原。

若数据不可得，应缩小研究范围或降低置信度，不得使用当前分类/修订值替代历史点时数据，也不得伪造精确成交。

## 13. 本阶段强制决策

- 所有数据必须具备来源、时间戳和质量状态。
- 关键财务、宏观和行业数据必须保留点时版本。
- 历史回测必须使用当时可知的股票池和分类。
- 所有信号必须关联数据快照、策略版本和参数版本。
- 所有回测必须可复现，失败实验必须保留。
- 数据质量否决优先于评分和交易信号。
- 先验收数据正确性，再评估策略收益。

## 14. 当前结论

本阶段完成统一数据架构与回测数据底座的规格设计，尚未接入生产数据、编写完整ETL或运行正式回测。下一步应先做数据源可得性与授权评估，再确定P0数据集和最小可行数据底座。
