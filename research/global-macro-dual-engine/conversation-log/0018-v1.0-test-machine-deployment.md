## 代码审查发现
V1.1存在以下不足：
1. BaoStock指数数据没有写入标准化目录，因而无法执行指数跨源比较。
2. AKShare指数只采集2019年，缺少近期窗口对照。
3. 缺少标准化数据结构质量检查，无法系统报告重复日期、无效日期、乱序和OHLC逻辑问题。
4. 部署说明不足，缺少隔离环境、跨操作系统安装步骤、输出清单和故障排查。
5. 运行成功和数据质量通过容易混淆，需要在文档中明确分离。

## V1.2修改
1. BaoStock指数也进入标准化流程。
2. AKShare指数增加近期窗口。
3. 指数纳入日期和OHLC/成交额跨源比较。
4. 新增基础质量检查报告data_quality_checks.csv。
5. 保留成交量单位未确认的限制，不做跨源成交量比较。
6. 新增测试机部署、运行、故障排查、验收清单和P0/P1/P2优化路线。
7. 已执行Python语法编译检查；未执行真实API采集。

## 当前结论
程序可进入测试机部署准备阶段，但尚未通过联网运行和真实数据质量验收。下一步必须以测试机真实输出形成实测报告，不能凭代码检查推断数据源质量。

## 第29阶段补充：V1.3部署前加固

用户要求继续推进研究与部署准备。重新检查V1.2脚本后发现固定输出目录存在旧文件污染风险：重跑时某个接口失败，旧标准化文件可能仍被本次比较逻辑读取。

本阶段将程序升级为V1.3：
1. 每次运行创建独立UTC Run ID目录，历史运行保留，不自动覆盖。
2. 比较仅读取当前Run目录，缺文件标记MISSING_FILE。
3. 比较前检查必需字段；缺字段标记MISSING_REQUIRED_COLUMNS。
4. 检测重复日期后停止该组跨源合并，避免多对多行数膨胀。
5. 增加OHLC空值、非正值、成交额空值质量字段。
6. 对本次raw/normalized CSV记录字节数和SHA-256。
7. manifest明确仍未完成交易日历、官方源核验、成交量单位跨源比较、授权审查和正式回测准入。

阶段边界：只完成代码静态审查和文档更新；没有在测试机运行，没有真实API下载，也没有数据源质量PASS结论。下一步仍需用户测试机运行，并回传同一Run ID目录中的三份报告。
