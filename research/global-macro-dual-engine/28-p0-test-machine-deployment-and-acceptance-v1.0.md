### E. 本轮验收结果的判定规则

- **PASS：** 有充分证据表明该项满足定义，且无未解释的关键异常。
- **CONDITIONAL：** 有部分证据，但存在需解释或限制使用的缺口。
- **FAIL：** 已确认不满足要求，或发现会影响研究结论的关键错误。
- **NOT_TESTED：** 没有实际测试证据。不能将未测试写成通过。

只有报告文件生成，不代表数据通过；两个数据源结果相同，也不代表两者一定正确。交易日历、证券生命周期和交易所公告仍需独立核验。

## 1. 部署边界

本程序是一次性小样本数据源审计工具，不是生产ETL、实时行情服务或正式回测数据底座。测试机运行成功只代表接口采集流程可运行，不代表数据源已通过质量验收，也不代表数据授权允许任意保存、商用或再分发。

建议先用独立测试目录和虚拟环境；不要直接接入交易账户、券商交易接口或实盘自动下单。

## 2. 推荐环境

- 操作系统：Windows 10/11、macOS或主流Linux 64位。
- Python：建议3.10–3.12；先在测试机确认兼容性，不建议直接使用系统Python。
- 网络：可访问BaoStock和AKShare所依赖的上游数据服务；企业网络代理、防火墙、DNS和证书拦截可能导致请求失败。
- 磁盘：预留至少1GB，实际输出通常远小于此值。
- 权限：普通用户权限即可；不需要管理员权限。
- 依赖：pandas、baostock、akshare，版本由requirements文件约束下限并在manifest中记录实际版本。

## 3. 安装与启动

### Windows PowerShell

```powershell
mkdir a_share_p0_test
cd a_share_p0_test
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements_p0_audit.txt
python -m py_compile p0_free_data_audit.py
python p0_free_data_audit.py
```

如PowerShell阻止激活脚本，可在当前终端使用：
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements_p0_audit.txt
.\.venv\Scripts\python.exe p0_free_data_audit.py
```

### macOS / Linux

```bash
mkdir -p a_share_p0_test && cd a_share_p0_test
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements_p0_audit.txt
python -m py_compile p0_free_data_audit.py
python p0_free_data_audit.py
```

将脚本和requirements文件放在同一目录。第一次运行建议前台运行，保留完整终端输出；不要先配置无人值守计划任务。

## 6. 运行故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| pip安装失败 | 网络、镜像、Python版本或证书问题 | 保存完整错误；先检查Python版本和网络，不要随意安装来源不明的wheel |
| BaoStock登录失败 | 上游服务、网络出口或服务维护 | 记录时间和错误码，稍后重试；不要将失败记为零行正常数据 |
| AKShare请求超时 | 上游网页接口变化、限流、网络问题 | 单独记录失败接口和时间；避免高频重试 |
| 某只股票返回空数据 | 代码、上市时间、退市历史覆盖或接口限制 | 对照上市/退市公告及交易日历，不直接判定为无交易 |
| 两源日期不一致 | 交易日口径、上市区间、停牌、源缺失或接口差异 | 逐日期对照交易所日历和公告 |
| 价格或成交额差异 | 复权口径、单位、精度、源数据修订 | 先核对字段定义与原始值，再决定是否可比 |
| 脚本运行中断 | 网络或上游服务异常 | 保存manifest/终端日志；本版本不保证断点续传，修复后可重新运行 |

不要把代理账号、密码、API密钥或个人目录路径上传到公开仓库。当前脚本不需要填写账户凭证。

## 8. 当前已知缺口与后续优化优先级

**P0：本轮部署前后必须处理**
1. 在目标测试机实际安装并运行，核验两个上游服务的真实接口状态。
2. 逐项复核AKShare成交量/成交额单位与接口版本；当前脚本不比较成交量。
3. 增加交易日历对照，区分非交易日、停牌日、接口漏数和证券生命周期边界。
4. 人工抽样核验OHLC、成交额和退市样本，不能只依赖两家第三方源互相证明。
5. 将“脚本运行成功”与“数据质量通过”分成两个独立状态。

**P1：进入更大样本前**
1. 增加指数数据和个股数据的独立覆盖率报告。
2. 增加数据行哈希、文件SHA-256、快照ID和可重复运行差异报告。
3. 增加请求重试上限、退避等待、单接口超时和失败汇总；重试不得造成重复数据被静默接受。
4. 增加公司行为、复权因子、停复牌、涨跌停状态的独立审计模块。
5. 扩充退市样本和不同年份/板块样本，建立历史股票池覆盖率测试。

**P2：正式回测前**
1. 建立交易日历与证券主表，统一证券生命周期。
2. 建立点时财报、公告、行业成分和宏观数据版本治理。
3. 完成未来函数、幸存者偏差、复权、停牌、涨跌停和T+1自动化测试。
4. 对数据许可做留档审查。
5. 只有全部关键数据测试通过，才开放策略历史回测；否则保持研究/暂停状态。
