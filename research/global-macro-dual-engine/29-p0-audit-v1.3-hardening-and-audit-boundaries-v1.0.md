# 第29阶段：P0采集程序V1.3部署前加固与审计边界

- 日期：2026-11-10
- 状态：代码与文档已更新；仅完成静态代码审查，未在测试机联网运行
- 对应程序：`p0_free_data_audit.py` V1.3
- 目标：消除重复运行的旧文件污染，增强异常暴露和审计可追溯性，降低误判风险。

## 1. 本阶段结论

V1.2采用固定的`raw/`和`normalized/`输出目录。若再次运行时某个接口失败，旧运行留下的标准化文件仍可能存在，后续比较逻辑可能读取旧文件。这会造成“本次采集失败、却使用上次数据完成比较”的审计污染。

因此V1.3改为每次运行创建独立UTC运行目录，不覆盖历史运行；比较只读取本次运行目录中的文件。

**本阶段没有真实下载行情，不代表BaoStock或AKShare可用，也不代表任何数据质量通过。**

## 2. V1.3修改

1. **运行隔离：** 每次运行生成UTC时间戳Run ID，报告和原始/标准化文件写入`p0_free_data_audit/runs/<run_id>/`。
2. **历史保留：** 不自动清空旧运行结果，避免破坏审计证据。
3. **比较防污染：** 仅在当前Run ID目录内查找文件，缺文件即标记`MISSING_FILE`。
4. **字段防御：** 比较前检查必需字段，缺字段输出`MISSING_REQUIRED_COLUMNS`，不让单个字段异常中断整个报告。
5. **重复日期保护：** 跨源比较前检查重复日期，发现重复标记`DUPLICATE_DATES`，不进行可能产生多对多膨胀的合并。
6. **质量检查扩展：** 增加OHLC空值、非正值、成交额空值检查；保留日期、重复和OHLC逻辑检查。
7. **文件指纹：** 对本次原始和标准化CSV记录文件大小及SHA-256，便于核对文件是否被改动。
8. **限制显式化：** manifest列出尚未完成的交易日历裁定、官方源抽样核验、成交量单位跨源比较、授权审查和生产/回测准入。

## 3. 新输出目录

每次运行输出：

```text
p0_free_data_audit/
  runs/
    20261110T150000Z/
      raw/
      normalized/
      manifest_and_results.json
      comparison_summary.csv
      data_quality_checks.csv
```

时间戳仅示意。请以实际生成的Run ID为准。三个报告不再直接位于旧版输出根目录，而位于本次Run目录中。

## 4. 部署命令

仍从仓库研究目录运行：

```bash
python -m py_compile p0_free_data_audit.py
python p0_free_data_audit.py
```

如使用独立测试目录，需将脚本和依赖文件放在同一目录。完整安装步骤仍见第28阶段部署手册。

## 5. 新版验收注意事项

- 只分析同一个Run ID目录下的三份报告。
- 不要把不同Run ID的报告混在一起比较。
- 每次重跑都会保留旧运行目录；请先确认磁盘空间，再决定是否归档或清理。
- SHA-256只证明文件字节指纹，不证明数据内容正确或来源合法。
- 比较状态为`COMPARED`也不等于数据通过；还需看日期覆盖、差异、单位、交易日历和官方抽样核验。
- 本次质量检查仍不是完整交易日历检查，停牌日、非交易日、接口漏数必须后续独立判定。
- 价格/成交额跨源一致也不能排除共同上游错误。
